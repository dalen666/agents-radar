#### 3. 共同关注的功能方向

以下功能需求在多个工具的社区中同时出现，是当前最普遍的开发痛点：

*   **模型兼容性与上下文窗口**:
    *   **Claude Code**: 关注第三方 API (Bedrock) 的兼容性报错。
    *   **OpenAI Codex**: 要求为 **GPT-5.5** 提供原生 **1M Token** 上下文支持 (#19464)。
    *   **Gemini CLI**: 未直接提及，但其 PR 旨在保持对话连续性 (#25290)。
    *   **Copilot CLI**: 要求与 VS Code Copilot 同步所有**组织启用的模型** (#1703)。
    *   **OpenCode**: 大量报告关于 **DeepSeek V4 Pro** 的**工具格式**和**字段解析**问题 (#24224, #24714)。
    *   **Qwen Code**: 多个 Bug 直指 **DeepSeek V4** 的 **`reasoning_content`** 传递导致 API 失败 (#3579, #3619)。
    *   **结论**: AI CLI 的核心价值正从“单模型绑定”向“**多模型路由器**”转变，但协议兼容性与非标准字段处理是重大瓶颈。

*   **后台任务管理与 Agent 鲁棒性**:
    *   **Kimi Code**: 聚焦于**审批流程**的自动化与超时配置 (#1823)。
    *   **Qwen Code**: 全方位推进后台任务管理，预计推出 `shell &` 的托管池和 `/tasks` 命令 (#3634)。
    *   **OpenCode**: 实现了 **`session move` / `detached`** 功能，让会话可迁移 (#24728)。
    *   **Copilot CLI & Gemini CLI**: 反复出现 Agent **无限循环**导致资源/配额耗尽的问题 (#2969, #3010, #25166, #26089)。
    *   **结论**: Agent 正从“一次性问答”进化到“**长期运行后台服务**”，如何安全、可控地管理这些后台任务是下一个技术高地。

*   **隐私与安全控制**:
    *   **OpenAI Codex**: 对**文件排除机制**的需求以绝对优势领先 (#2847, 347👍)。
    *   **Kimi Code**: 实现了可配置的**自动审批规则** (#2092, #2095)。
    *   **Gemini CLI**: 通过 PR 修复了敏感文件的**目录权限** (#26063)。
    *   **Copilot CLI**: 新版本默认启用了基于目录的**权限持久化**。
    *   **结论**: 用户不希望 AI 接触所有文件，也不希望为每一次操作弹窗确认，**细粒度、自动化、可配置的权限系统**是成熟的必备特性。

#### 5. 社区热度与成熟度

*   **成熟社区 (高活跃, 关注稳定性)**: **Claude Code** 和 **OpenAI Codex** 的社区已非常庞大，讨论从“如何用”转向“如何更好更稳地用”，Bug 修复和功能请求非常具体，生态成熟度最高。
*   **高速迭代期 (功能不断涌现)**: **Kimi Code**、**Qwen Code** 和 **OpenCode** 正处于此阶段。它们积极吸收社区反馈，快速推出 PR 和修复，功能路线图清晰，是技术创新最活跃的群体。
*   **生态整合期 (端到端体验)**: **Copilot CLI** 和 **Gemini CLI** 受到母公司生态的深刻影响，其更新与 GitHub IDE 和 Google Cloud 更新同步。社区热度高，但对 Bug 的容忍度较低，一旦出问题（如无限消耗额度）会迅速引发信任危机。
*   **探索期 (小而美)**: **Pi** 社区相对小众，但以其独特的“包管理”概念和积极的第三方 Provider 支持（如 Cloudflare），培养了一批忠实的高级用户，探索技术前沿。

#### 6. 值得关注的趋势信号

1.  **“模型路由器”将成主流**: 社区对非官方模型的支持诉求已从“能不能用”变为“能不能完美用”。AI CLI 自身模型能力的价值正在被稀释，其**核心资产将转变为对多模型的高效、透明、稳定路由能力**，包括处理非标准字段、格式转换、协议适配等。

2.  **Agent 必须“可观察、可控制”**: 无限循环、后台静默消耗资源、权限滥用是开发者最担心的问题。未来的 CLI 需要像现代云原生应用一样，提供**资源配额仪表盘、任务监控面板和精细化权限审计**。Copilot 的无限消耗问题就是一个最好的例子。

3.  **“安全护栏”成为基础设施**: OpenAI Codex 社区的 #2847 (347赞) 揭示了一个根本性需求：开发者需要工具能识别并排除“绝对禁区”。这类**`.codexignore` 或 `--exclude` 模式**将从可选功能升级为必备基础设施，且需要更智能的上下文感知。

4.  **MCP 协议的价值链迁移**: MCP 从“连接工具”上升为“连接效率”。Claude Code 的 `alwaysLoad` 和 Kimi Code 的“自动审批 MCP 工具”表明，社区对 MCP 生态的关注点已从“有哪些工具”转向“**如何高效、无感地使用工具**”。

5.  **平台兼容性是“隐形门槛”**: WSL 下的崩溃 (Gemini)、macOS 下的路径空格 (Claude) 等问题证明，在拓展用户群时，**跨平台（尤其是 Linux 和 WSL）的稳定性和测试**是决定工具成败的“最后一公里”关键因素，其重要性不亚于新功能的开发。
